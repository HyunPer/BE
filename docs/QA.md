# QA 기록

화면이 나오기 전까지는 세 겹으로 QA한다.

| 층 | 방법 | 실행 |
| --- | --- | --- |
| 서버 통합 테스트 | MockMvc로 API 전체, 예외·권한·동시성 포함 | `./gradlew test` (BE) |
| 클라이언트 E2E | FE `core-api`가 실제 서버를 상대로 데모 시나리오 전체 | `PLEOS_E2E_BASE_URL=http://localhost:8090/ ./gradlew :core-api:test` (FE) |
| 임시 화면 QA | `/qa` 콘솔: 손으로 눌러보기 + 자동 QA 20단계 | 서버 실행 후 `http://localhost:8090/qa/` |

## 2026-10-27

### 결과

- 서버 통합 테스트 **41개 통과** (QA 경계 5, 멤버 관리 5, QA 콘솔 3 추가)
- FE 단위 9개 + 실제 서버 대상 E2E 1개 통과, 폰·차량 디버그 APK 빌드
- QA 콘솔 자동 QA **20/20 통과** (내장 브라우저에서 실행), 데모 가족 생성 → 탑승 2단계 적용 → 테마가 입혀진 차량 화면 렌더링 확인

### 찾아서 고친 버그

| # | 증상 | 원인 | 조치 |
| --- | --- | --- | --- |
| 1 | 같은 차의 다른 MEMBER가 남의 다음 운전자 예약을 취소할 수 있음 | 취소 시 멤버 여부만 검사 | 예약한 사람이나 OWNER만 취소, 그 외 403 |
| 2 | 같은 사람이 페어링을 빠르게 여러 번 누르면 500 | 동시 삽입이 (차량, 사용자) 유일 제약에 걸림 | 페어링 시 차량 행 비관적 잠금, 제약 위반은 409로 응답 |
| 3 | 두 사람이 동시에 첫 페어링하면 OWNER가 둘 생길 수 있음 | "멤버가 없으면 OWNER" 판단이 동시 실행됨 | 위 잠금으로 순서대로 처리 (4명 동시 페어링 × 3회 테스트) |
| 4 | 예상하지 못한 예외가 ProblemDetail이 아닌 기본 오류로 나갈 수 있음 | 전역 처리기에 일반 예외 처리 없음 | 500 ProblemDetail(내부 정보 숨김) + 서버 로그 |

### 확인한 경계 (모두 기대대로)

- 잘못된 UUID·JSON·enum·길이·위젯 개수·공유 코드 형식·빈 multipart → 400 ProblemDetail
- 없는 경로 404, 잘못된 메서드 405, 없는 리소스 404
- Authorization 변형(빈 Bearer, Basic, 소문자 bearer + 틀린 토큰, 빈 값) → 401
- 사용자 토큰·차량 토큰 섞어 쓰기 → 401
- GIF·이미지 아닌 파일 업로드 → 400, PNG 업로드 후 토큰 없이 내려받기
- 글자 대비 부족 테마 → 400(한국어 설명), 남의 이미지·남의 테마 사용 → 404
- 적용 완료 보고 재시도 → 같은 웰컴 묶음, 취소된 예약 보고 → 409
- 멤버 이탈 시 대기 예약 취소·그 차 시트 자세 삭제, 프로필은 유지
- OWNER는 다른 멤버가 있으면 넘기기 전 나갈 수 없음(409), MEMBER의 OWNER 기능 호출 403

### 남은 확인 거리

- 실제 Pleos 에뮬레이터·Vehicle SDK에서 2단계 적용 (SDK 저장소·권한 확인 후)
- 배포 환경(HTTPS, PostgreSQL)에서 같은 시나리오 재실행
- 이미지 공개 주소를 만료 주소로 바꾼 뒤 재검증
